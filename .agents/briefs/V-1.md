# V-1 · vectorcraft: `<title>` names on SVG import, step references in `run`

Branch `agents/V-1`, PR to `zokito/vectorcraft` `main` only. Follow the repo's own
CONTRIBUTING/AGENTS docs and code style. File:line references come from an analysis of commit
44e4e63; `main` has moved (one commit touched import.rs or the CLI), so verify before editing.

## Context (verified by analysis)
- Import already maps `id` / data-name / inkscape:label / serif:id / aria-label to object names
  (crates/svg/src/import.rs ~466-482 `labels()`, ~604 `name_of()`, ~609-616 `named()`), and
  export writes the name back as `id` (export.rs ~531-556). Do not change that behaviour.
- Missing (V1a): a `<title>` child is not used as a name.
- Missing (V2): apps/vectorcraft-cli/src/main.rs ~248-253, the `run` loop sends each `--cmd`
  with static params and discards the result; no command accepts a name (engine `id_param`
  crates/engine/src/cmd/mod.rs ~295 takes u64 only).

## Do
1. V1a: in `labels()`, when no other label exists, use the trimmed text of a direct `<title>`
   child (give the element an id via `Edits::id` if it needs one). Made-up ids must stay unnamed.
2. V2: in the CLI `run` loop keep `results: Vec<Value>` (one per `--cmd` step, 1-based).
   Before each call walk its params; a JSON string matching `^\$\d+(\.|\[)` exactly (whole
   string) is replaced by the value at that path in step N's result
   (e.g. `"$1.matches[0].id"`); `"$$..."` is the escape for a literal leading `$`. Missing step
   or path: non-zero exit with a message naming the reference. Only `--cmd` steps count.
   CLI only: do not change engine, journal or MCP.
3. Document both in docs/mcp.md (§ Headless batch CLI) and README if it lists run options.
4. Out of scope: native rect/ellipse live shapes (V-2, later), the PNG "ghost text" (not a bug).
