# V-2 · vectorcraft: import SVG rect/circle/ellipse as live shapes

Branch `agents/V-2`, PR to `zokito/vectorcraft` `main` only. Follow the repo's own
CONTRIBUTING/AGENTS docs and code style. Builds on V-1 (merged): ids, data-name and `<title>`
already become object names; keep that behaviour.

## Context (verified by analysis; verify lines on current main)
- usvg turns `<rect>`, `<circle>`, `<ellipse>` into plain paths; import sets `live: None`
  (crates/svg/src/import.rs, `NodeKind::Path { .., live: None, .. }` ~1092 in `path()`).
- The document model already has live shapes: `LiveShape::Rectangle { w, h, radii, kinds, xf }`
  and `LiveShape::Ellipse { w, h, xf, .. }` (crates/doc/src/node.rs ~79-150), shown in the UI
  as "Rectangle", "Rounded Rectangle", "Ellipse".

## Do
1. Before usvg conversion, collect from the roxmltree source a map id → (tag, x, y, w, h,
   rx, ry / cx, cy, r, rx, ry); give unnamed rect/circle/ellipse elements a made-up id via
   `Edits::id` so they can be matched (made-up ids must stay unnamed, as today).
2. In `path()`, when the node came from such an element and its absolute transform is a
   similarity (uniform scale + rotation + translation, no skew), set
   `live: Some(LiveShape::Rectangle{..})` (rx/ry → radii) or `Some(LiveShape::Ellipse{..})`
   with the transform in `xf`; the geometry must equal what `path` already contains (±1e-6).
   Otherwise keep `live: None`.
3. Export may keep writing `<path>`; optional: write `<rect>`/`<ellipse>` for untransformed
   live shapes only if roundtrip tests stay green.
4. `path.setAnchors` on a live shape turns it into a plain path (existing behaviour); do not change.
